要搞懂 DRI 是干嘛的，咱们得先看看以前没有它的时候，图形程序是怎么受憋屈的：

## 1. 以前的做法：间接渲染（Indirect Rendering）

在早期的 X11 桌面时代，假设你要跑一个 3D 游戏，游戏程序自己是不能直接去摸显卡的。
它得把所有的 OpenGL 画图指令先打包，像寄快递一样发给 X Server（桌面大管家），然后由 X Server 再去调用显卡驱动把图画出来。这种做法叫“间接渲染”。
**结果就是：** 慢！太慢了！中间倒了一手，数据传来传去，CPU 消耗极大，玩个 3D 游戏根本带不动。

## 2. DRI 的诞生：直接渲染！

为了打破这个瓶颈，大佬们搞出了 DRI 这套架构。它的核心思想就俩字：**直连**。下图绿色的直连通道：

![alt text](/assets/images/ubuntu-开发指南/什么是dri-直接渲染架构/Linux_Graphics_Stack_2013.svg)

有了 DRI 之后，系统里的分工就变成了这样“铁三角”配合：

- **干活的（客户端程序 + Mesa 3D 驱动）：**
  你的程序（比如 Qt 写的 3D 界面）加载了用户态的显卡驱动（通常是 Mesa）。Mesa 知道显卡的脾气，它把 OpenGL 指令翻译成显卡认识的机器码。
- **管纪律的（X Server / Wayland）：**
  大管家不再插手具体的画图过程了。它只负责告诉你：“兄弟，你在屏幕上的坐标是 (100, 100)，窗口大小是 800x600，别画出界了啊。”
- **开绿灯的（内核里的 DRM）：**
  DRM 也就是咱们上一把聊的。它给你的程序分配好显存，然后批准你直接把翻译好的画图指令塞给显卡硬件。

**这就是 DRI 的真面目：** 它允许用户态的程序，在安全的前提下，**绕过显示服务器（X Server），直接把渲染指令发送给内核层的 DRM，最后直达 GPU 硬件。**
