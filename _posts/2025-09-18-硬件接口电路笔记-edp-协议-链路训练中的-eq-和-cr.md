- **​​CR（Clock Recovery，时钟恢复）** 解决的是 **“何时采样”** 的问题，确保接收端能在正确的时间点读取数据。
- **​EQ（Channel Equalization，通道均衡）** 解决的是 **“信号质量”** 的问题，补偿传输过程中受损的信号，使其变得清晰可辨。

---

## 1. CR - Clock Recovery（时钟恢复）

### 核心概念

在高速串行通信中（如 eDP, USB, PCIe），为了节省引脚数量和降低干扰，通常**不会有一根独立的时钟线**与数据线一起传输。相反，时钟信息是“嵌入”在数据流本身的跳变（从 0 到 1 或从 1 到 0）中的。

**时钟恢复就是接收端电路从输入的数据流中提取出时钟信号的过程。**

### 为什么需要它？

1.  **没有独立的时钟线**：发送端和接收端有各自独立的时钟源，它们之间存在微小的频率和相位差异（时钟漂移）。如果没有一个共同的参考时钟，接收端很快就会出现采样错误。
2.  **同步**：接收端需要生成一个与输入数据完全同步的时钟，确保在每个数据比特的中间（最稳定的时刻）进行采样，而不是在跳变边缘（最容易出错的时刻）。

### CR 流程

![alt text](/assets/images/硬件接口电路笔记/edp-协议-链路训练中的-eq-和-cr/image-1.png)

1. **Transmit TPS1**
   源端发出 **Training Pattern 1**（TPS1）信号，初始用最大 lane、最大速率。

2. **检查是否完成 CR**

   - 如果 **CR Done**，流程结束。
   - 如果没完成，继续调整。

3. **Adjust Drive Levels**
   源端调节 **驱动电压摆幅 (VOD) 和预加重** 参数。

4. **检查是否达到最大驱动电平或已尝试 5 次**

   - 如果是 → 降低链路速率 / lane 数，回退重新训练。
   - 如果不是 → 继续尝试。

5. **回到 CR Done**，直到完成或降速。

👉 简单理解：Clock Recovery 就是在调试“链路的时钟锁定”，像调收音机频率，直到接收端能正确锁定时钟。

## 2. EQ - Channel Equalization（通道均衡）

### 核心概念

当高速信号通过主板上的走线、连接器（FPC 排线）传输到显示面板时，会遇到物理通道的损伤：

- **高频衰减**：通道像是一个低通滤波器，信号的高频成分（对应快速的 01 跳变）比低频成分衰减得更厉害。这导致信号变得“圆滑”， blurry（模糊），码间干扰（ISI）严重。
- **反射和串扰**：阻抗不匹配和相邻信号线的干扰也会进一步恶化信号质量。

**通道均衡是一种“整形”技术，在接收端或发送端对信号进行预处理或后处理，以补偿通道造成的高频损耗，使接收到信号眼图重新张开。**

### 为什么需要它？

没有均衡，受损的信号在接收端会无法被正确识别，导致误码率飙升，屏幕可能出现花屏、闪烁、撕裂等问题。

### EQ 流程

![alt text](/assets/images/硬件接口电路笔记/edp-协议-链路训练中的-eq-和-cr/image.png)

1. **Transmit TPS2/3/4**
   源端发出训练图案 TPS2 / TPS3（DP1.4+ 加上 TPS4），使用前面 CR 确定的配置。

2. **Reset Loop Count & Read Status Bits**
   重置循环计数，并读取接收端反馈状态。

3. **检查 CR 和 EQ 是否完成**

   - 如果 **CR Fail** → 回到 CR 重新来。
   - 如果 **EQ Fail** → 调整驱动电平，或者减速 / 减 lane。

4. **Loop Count 限制**
   通常限制尝试次数（>5 次则降速）。

5. **如果最低速率/lane 也不行 → 训练失败**
   否则，最终 **EQ Done → 结束 Link Training**。

👉 EQ 阶段就是确保“信号完整性”，避免数据在高速通道中失真。
