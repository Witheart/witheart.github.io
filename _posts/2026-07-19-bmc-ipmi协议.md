**IPMI**（Intelligent Platform Management Interface，智能平台管理接口）是一项由 Intel、Dell、HP 和 NEC 联合提出的服务器硬件管理标准化协议。

它的核心作用是：**允许系统管理员远程监控、管理和控制服务器硬件**，且这一切**完全独立于服务器的主 CPU、BIOS 和操作系统**。


![alt text](/assets/images/bmc/ipmi协议/image.png)

## 核心大脑：BMC（基板管理控制器）

IPMI 协议本身只是一套规范，真正执行这套规范的是主板上的一块独立微控制器——**BMC（Baseboard Management Controller）**。

你可以把 BMC 想象成服务器主板上的“影子电脑”。它拥有自己的独立处理器和内存。只要服务器插着电源（哪怕处于关机状态，只要有待机电流），BMC 就在独立运行并监听外部指令。

## IPMI 的四大核心能力

| 功能                   | 具体作用                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| **带外管理 (OOB)**     | 这是 IPMI 最大的价值。即使操作系统崩溃蓝屏，只要网线和电源线连着，管理员就能绕过 OS 直接控制硬件。 |
| **远程电源控制**       | 允许管理员远程执行开机、关机、硬重启（Reset），效果等同于人在机房物理按下服务器的电源键。          |
| **硬件遥测监控**       | 通过主板上的传感器网络，实时读取 CPU 温度、电压、风扇转速、电源模块状态等底层数据。                |
| **系统事件日志 (SEL)** | 自动将硬件级别的告警（如温度越限、风扇停转、内存 ECC 错误）记录到非易失性存储器中，断电不丢。      |

## 内部与外部是如何通信的？

IPMI 定义了非常严谨的通信接口，主要分为三类：

1. **IPMI over LAN（外部通道）：** 管理员通过以太网向服务器发送 UDP 数据包。常用的开源工具如 `ipmitool` 就是通过这个通道远程发送指令的。各大服务器厂商的 Web 管理界面（如 Dell iDRAC、HP iLO）底层也大量依赖 IPMI 规范。
2. **IPMB（内部总线）：** 智能平台管理总线（Intelligent Platform Management Bus）。这是主板内部各个传感器、外围设备与 BMC 通信的通道，其物理层和数据链路层通常基于 **I2C / SMBus** 协议。
3. **系统接口（本地通道）：** 如 KCS（Keyboard Controller Style）。它允许服务器正在运行的操作系统（如 Linux 里的 `ipmi_si` 驱动）直接与底层的 BMC 进行本地数据交换。

## 现状与演进

IPMI 是过去二十年数据中心硬件管理的绝对基石。不过，由于 IPMI 的设计年代较早，其安全性（存在一些已知漏洞）和扩展性逐渐遇到瓶颈。目前，基于 RESTful API 和 JSON 格式的 **Redfish 协议** 正在成为下一代标准，但 IPMI 依然作为最基础的底层协议被广泛兼容和保留。
