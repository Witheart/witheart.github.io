```bash
wlan0 IEEE 802.11 ESSID:"Xiaomi_49DE_5G"  
Mode:Managed Frequency:5.785 GHz Access Point: 50:88:11:A2:49:E0  
Bit Rate=433.3 Mb/s Tx-Power=31 dBm  
Retry short limit:7 RTS thr:off Fragment thr:off  
Power Management:off  
Link Quality=62/70 Signal level=-48 dBm  
Rx invalid nwid:0 Rx invalid crypt:0 Rx invalid frag:0  
Tx excessive retries:2 Invalid misc:0 Missed beacon:0  

```

### 1. 基础连接信息 (Association Info)

这一部分定义了你的网卡当前“连接到了谁”，以及“处于什么工作状态”。

- **`ESSID:"Xiaomi 49DE 5G"`**
- **含义：** 扩展服务集标识符，也就是我们常说的 **Wi-Fi 名称**。

- **`Mode:Managed`**
- **含义：** 网卡的工作模式。`Managed`（管理模式，也叫 Station 模式）是绝大多数客户端设备的默认模式，表示你的网卡作为一个“终端节点”，受控于一个中心化的无线路由器（AP）。_（作为对比，如果你在做热点分享，这里会是 `Master`；如果你在做无线网络抓包，这里会是 `Monitor` 监听模式）。_

- **`Frequency:5.785 GHz`**
- **含义：** 当前工作的中心射频频率。5.785 GHz 对应的是 5G Wi-Fi 频段中的 **157 信道**。

- **`Access Point: 50:88:11:A2:49:E0`**
- **含义：** 也就是 BSSID，你当前连接的那个路由器的**物理 MAC 地址**。在多 AP 漫游环境（如 Mesh 网络）中，即使 ESSID 名字一样，你也可以通过这个地址判断设备连在哪个具体的节点上。

---

### 2. 射频与链路参数 (Radio & Link Parameters)

这一部分反映了无线电波底层的协商能力和发送策略。

- **`Bit Rate=433.3 Mb/s`**
- **含义：** 物理层协商的**瞬时最大理论速率**。
- **专业解析：** 这个数值不是你真实的下载网速，而是底层 MCS（调制与编码策略）的指标。433.3 Mbps 是一个非常经典的数值，它通常代表你的网卡和路由器之间使用 **802.11ac (Wi-Fi 5) 协议，工作在 80MHz 频宽下，并且只使用了单根天线 (1x1 MIMO)** 进行通信。

- **`Tx-Power=31 dBm`**
- **含义：** 网卡射频芯片的发射功率。
- **专业解析：** 31 dBm 换算过来大约是 **1258 毫瓦 (1.25W)**。对于普通的终端网卡来说，这个发射功率是非常高的（一般手机或笔记本在 15~20 dBm 左右）。这意味着这块网卡（或其外置 PA 功放）拥有极强的信号发送能力。

- **`Retry short limit:7`**
- **含义：** MAC 层短帧重传上限。当网卡发送一个没有启用 RTS/CTS 机制的普通数据帧时，如果收不到路由器的 ACK 确认，硬件最多会在底层重试 7 次。超过 7 次仍失败，就会丢弃该帧并向上层报错。

- **`RTS thr:off` / `Fragment thr:off**`
- **含义：** RTS/CTS 握手阈值与分片阈值。`off` 表示关闭。
- **专业解析：** 在非常拥挤、存在大量“隐藏节点”的工业或公共无线环境中，开启这两个参数可以减少物理冲突，但在你目前良好的网络环境下，关闭它们能减少控制帧的开销，提高传输效率。

- **`Power Management:off`**
- **含义：** Wi-Fi 芯片组的电源管理状态。`off` 意味着网卡处于**全速运行（Active mode）**，不会进入睡眠状态（休眠时会向 AP 发送 PS-Poll 帧）。这会增加功耗，但在低延迟和高吞吐场景下是必须的。

### 3. 信号质量 (Signal Metrics)

这里是驱动程序对当前空中电磁环境的评估。

- **`Link Quality=62/70`**
- **含义：** 链路质量得分。这是一个由网卡驱动程序计算出的综合指标（不同的驱动计算公式可能不同）。62/70 表示当前的连接质量非常优秀，抗干扰能力很强。

- **`Signal level=-48 dBm`**
- **含义：** RSSI（接收信号强度指示）。
- **专业解析：** 无线信号强度是用负数表示的，**越接近 0 信号越好**。
- `-30 到 -50 dBm`：极佳（通常设备和路由器在一个房间内）。
- `-60 到 -70 dBm`：良好到中等（隔了一堵墙）。
- `-80 dBm 以下`：极差，经常会掉线或丢包。

- 你的 `-48 dBm` 说明设备离路由器很近或者天线增益很好，信号接收状态极佳。

---

### 4. 统计与错误计数 (Error Counters)

这部分是底层的异常统计，比我们之前看的 `ifconfig` 更贴近无线物理层。

- **`Rx invalid nwid:0` / `crypt:0` / `frag:0**`
- **含义：** 接收时发生的底层错误。
- `nwid`: 收到了网络 ID (ESSID) 不匹配的帧（通常被硬件过滤）。
- `crypt`: 硬件解密失败（比如 WPA2/WPA3 密钥错误，或者密文被空中干扰破坏）。
- `frag`: 硬件在重组分片帧时失败。

- 你的全为 0，说明接收端在硬件处理逻辑上完全没有异常。

- **`Tx excessive retries:2`**
- **含义：** 发送过度重试次数。
- **专业解析：** 之前提到的 `Retry short limit` 是 7。这里数值为 2，说明自从网卡启动以来，**只有 2 个数据包** 在尝试发送了 7 次之后依然没有收到路由器的 ACK，最终被 MAC 层放弃了。这在充满波动的无线电环境中是极其微小的概率，完全可以忽略不计。

- **`Invalid misc:0`**
- **含义：** 其他无法归类的杂项错误，为 0 正常。

- **`Missed beacon:0`**
- **含义：** 漏听到的信标帧数量。
- **专业解析：** 路由器（AP）默认每 100 毫秒会在空中广播一次 Beacon（信标帧）来宣告自己的存在。如果你的网卡由于干扰或者自身卡顿，错过了这些信标，这个数值就会增加。大量丢失信标会导致系统认为路由器已经掉线，从而触发重新扫描或断网。你的数值为 0，说明网卡和路由器之间的“心跳”非常稳定。

## 例子

- **3588 网络崩溃，经查excessive偏多：** 最后发现问题是WiFi模组休眠后概率性无法唤醒，导致网络崩溃。WiFi无法唤醒，接收不到AP的ACK，导致excessive偏多。
