## **功能名称：HW-ID DTB**

---

## **参考资料**

1. **程序 SDK 根目录下**：`RKDocs/common/u-boot/Rockchip_Developer_Guide_UBoot_Nextdev_CN.pdf`，见 P60
2. **正点原子开发手册**：`02【正点原子】ATK-DLRK3568_Android系统开发手册V1.2.pdf`，见 P137

---

## **原理说明**

HW-ID DTB 功能通过硬件识别（如 GPIO 或 ADC）来动态选择设备树（DTB）。在系统启动时，u-boot 会根据硬件状态（如拨码开关的 GPIO 电平或 ADC 的电压值）加载对应的设备树，从而实现对不同硬件配置的支持。

- **GPIO 硬件识别**：通过读取 GPIO 引脚的状态，判断硬件配置并选择对应的设备树。
- **ADC 硬件识别**：通过读取 ADC 的电压值范围，确定硬件配置并选择设备树。

---

## **开发流程**

1. **修改设备树文件**
   在`u-boot/arch/arm/dts/rk3568-u-boot.dtsi`中，确保 GPIO 或 ADC 硬件检测节点的配置正确：

   - **GPIO 检测**：在`&pinctrl`和对应的`&gpio`节点中添加属性`u-boot,dm-spl`和`u-boot,dm-pre-reloc`，使这些节点在 u-boot 早期阶段就可以被访问。
   - **属性说明**：
     - `u-boot,dm-spl`：表示该节点在 SPL 阶段可用。
     - `u-boot,dm-pre-reloc`：表示该节点在设备重定位之前可用。

   示例代码：

   ```dts
   &pinctrl {
       u-boot,dm-spl;
       u-boot,dm-pre-reloc;
       status = "okay";
   };

   &gpio2 {
       u-boot,dm-spl;
       u-boot,dm-pre-reloc;
   };
   ```

   - **ADC 检测**：默认情况下，ADC 硬件检测功能已经使能，无需额外配置。

2. **编译设备树**
   为每个硬件配置生成对应的设备树文件（DTB），并使用自定义命名区分这些设备树。例如：

   - `rk3568_hwid1.dtb`
   - `rk3568_hwid2.dtb`

3. **打包设备树**
   使用`mkmultidtb.py`脚本将所有设备树文件（DTB）打包到`resource.img`中。具体操作参考《使用 mkmultidtb.py 打包多个设备树》。打包完成后，`resource.img`会自动放置到`./kernel`目录下，覆盖原有的`resource.img`。
4. **注意**：
   `mkmultidtb.py`脚本只是打包并替换了`./kernel`目录下的`resource.img`，而`./kernel`目录下的`boot.img`中包含的`resource.img`还是旧的，不是`mkmultidtb.py`脚本打包出来的，且`./kernel`目录下的`boot.img`中不包含最终烧录所需的`ramdisk.img`，所以需要进行下一步得到烧录用的真正`boot.img`。
5. **生成`boot.img`**

   - 确保`kernel`目录下的`resource.img`已被正确替换。
   - 进入 SDK 根目录，执行以下命令：
     ```bash
     make bootimage -j16
     ```
   - 该命令会将`resource.img`打包为包含`ramdisk.img`的`boot.img`，生成的`boot.img`路径为：
     ```
     <sdk>/out/target/product/<产品名称>/boot.img
     ```

6. **烧写镜像**
   使用烧录工具将生成的`boot.img`烧写到开发板的`boot`分区中，确保系统能够加载正确的设备树。

---

## **问题与解决方案**

- 替换`kernel`目录下的`resource.img`后，执行`make bootimage -j16`命令时，`<sdk>/out/target/product/rk3568_HW/boot.img`文件有时不会更新。

### **可能原因**

1. **Makefile 依赖未触发**：`make`系统可能未检测到`resource.img`的变化，导致未重新生成`boot.img`。
2. **编译缓存问题**：编译系统可能使用了旧的中间文件，未正确更新。

### **解决方案**

1. **重新编译内核**：
   进入 sdk 根目录后：
   ```bash
   ./build.sh -CK
   ```
