[github issues #9428](https://github.com/1Panel-dev/1Panel/issues/9428)

### 环境信息
- **操作系统**：Ubuntu 22.04.1 LTS
- **1Panel版本**：v1.10.29-lts
- **磁盘配置**：系统盘128GB + 数据盘4TB（备份目标盘）

### Problem Description

当使用1Panel的`定时备份目录`功能备份大文件（>128GB）时：
1. 虽然指定了外部备份存储路径（如 `/mnt/nvme`）
2. 但压缩过程仍强制使用系统盘临时目录 `/opt/1panel/tmp`
3. 导致系统盘被完全占满
4. 最终引发 **`1panel disk I/O error (4874)`** 面板服务崩溃

### Steps to Reproduce

1. 配置定时目录备份任务（指向大容量数据目录，如 >128GB）
2. 观察备份执行过程：
   bash
   # 关键进程展示：
   root      50264  2.9  0.0   9864  3200 ? S  17:32 0:00 tar ... -zcf /opt/1panel/tmp/.../directory_mnt_nvme_...tar.gz ...
   root      50269 96.7  0.0   3528  1920 ? R  17:32 0:26 gzip

3. 等待系统盘空间持续消耗至100%
4. 面板服务不可用并报错


### The expected correct result

1. 压缩过程应在**用户指定的备份存储路径**（如 `/mnt/nvme/backups`）创建临时文件
2. 或提供临时目录配置选项
3. 系统盘空间不应被备份任务占用

### Additional Information

## 故障分析
1. **关键错误**：备份过程分两步
   - 先在系统盘生成压缩包：`/opt/1panel/tmp/xxx.tar.gz`
   - 再（可能）移动到目标存储位置
2. **设计缺陷**：未考虑系统盘容量限制，对大型备份操作缺乏保护机制
