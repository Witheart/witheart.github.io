**DMI（Direct Media Interface）是 Intel 平台中，CPU 和 Chipset（PCH）之间的“内部高速互联总线”，本质上是一个“定制版 PCIe 链路”。**

它**不是给外设用的**，而是 **CPU ↔ PCH 的专用通道**。


## 参考链接
https://en.wikipedia.org/wiki/Direct_Media_Interface

## 一、为什么需要 DMI？（架构背景）

先看一个**现代 Intel 平台的分工**：

### CPU 里已经有什么？

- 核心（Core）
- 内存控制器（IMC）
- PCIe Root Complex（给显卡 / NVMe）
- 有时还包括部分 IO（USB4 / Thunderbolt）

### 那 Chipset（PCH）还剩什么？

- SATA
- USB（2.0 / 3.x）
- 网卡（MAC）
- SPI / LPC / I2C / SMBus
- HD Audio
- 一堆低速 / 管理型外设

👉 **问题来了**：
这些 PCH 里的设备，怎么访问 CPU 和内存？

**答案：靠 DMI**

---

## 二、DMI 的本质：它到底“像什么”？

### 1️⃣ 协议层面

> **DMI ≈ PCIe（电气 + 传输）**

- 物理层：**PCIe PHY**
- 链路层：类似 PCIe
- 事务：TLP 风格

但：

- 不是标准 PCIe
- 不可枚举
- 不对外公开拓扑

可以理解为：

> **Intel 内部用的一条“私有 PCIe 总线”**

---

### 2️⃣ 拓扑视角

```
            ┌───────────┐
            │    CPU    │
            │           │
            │  PCIe RC  │───── GPU / NVMe
            │           │
            │   DMI     │
            └─────┬─────┘
                  │
          =================  ← DMI Link
                  │
            ┌─────┴─────┐
            │    PCH    │
            │           │
            │ SATA USB  │
            │ LAN Audio │
            └───────────┘
```

👉 **PCH 在系统里看起来就像：**

> 一个**挂在 CPU 后面的巨大 PCIe 设备集合**

---

## 三、DMI 的带宽与代际（你会真的踩坑的点）

### 常见 DMI 版本 & 等效 PCIe

| DMI 版本 | 等效 PCIe | 通道数 | 理论带宽（单向） |
| -------- | --------- | ------ | ---------------- |
| DMI 2.0  | PCIe 2.0  | x4     | ~2 GB/s          |
| DMI 3.0  | PCIe 3.0  | x4     | ~4 GB/s          |
| DMI 4.0  | PCIe 4.0  | x4     | ~8 GB/s          |

⚠️ **重点**：

你会遇到这种现象：

- 插了多个 USB3 + SATA + PCH NVMe
- 同时拷贝数据
- 性能“诡异变慢”

原因往往不是驱动，而是：

> **DMI 带宽被打满了**

---

## 四、为什么 AMD 没有 DMI？

这个对比你一定会好奇 👀

### AMD 平台

- CPU：集成更多 IO
- CPU ↔ 芯片组：

  - 早期：UMI
  - 新平台：**PCIe x4 直连**

👉 **AMD 本质上是：**

> 用“标准 PCIe”当 DMI 用

而 Intel 选择：

> 自己定义一套“受控、封闭、稳定”的 DMI
